# Tool playbooks

Use the same validated chart spec across targets. Verify the runtime and official guidance before choosing an implementation, especially for native authoring and export.

| Target | Build approach | Verify in the target |
| --- | --- | --- |
| Figma | If the authorized Figma MCP can write, use the installed Figma authoring skills, inspect existing design tokens, and create native editable frames, labels and marks. Keep the data and transforms in a separate reproducible spec. | Inspect the canvas and change a label/mark in a review copy if permitted. A frame does not establish live refresh, working filters, or production accessibility. Without write access provide a layout spec and optional SVG, labeled as an export. |
| Power BI | Define grain and model relationships; use explicit, context-aware measures for ratios. Prefer built-in visuals; configure sort, filters, themed colors, alt text, tab order and accessible data views. | Confirm the values under multiple filters, report interactions, keyboard order, and export/suppression behavior. If the environment cannot author or open the requested report, deliver DAX, model assumptions, and assembly steps; mark the native report not built. |
| Python | Separate loading/transforms from plotting. Use an appropriate installed library such as Matplotlib for static output; pin dependencies and export source plus the requested SVG/PDF/PNG. Include a text alternative. | Independently verify transformed values and visually inspect the exported artifact, including fonts and labels. Verify in the intended editor before claiming the exported file is editable there. |
| D3 / web | Use scales with explicit domains, keyed joins, responsive layout, keyboard-accessible filters where relevant, and a chart description or data table. Handle empty, filtered, and missing states. | Run in a browser at relevant sizes; test default and changed filters, keyboard focus, and the no-data state. Inspect DOM data exposure, not just what is painted. |
| Excel / PowerPoint | Use a real chart object and an approved workbook or embedded table, not a screenshot. Use native chart tooling supported in the user's environment. Keep data provenance, style, and accessibility notes with the artifact. | Open the actual Office artifact and change an allowed test value to confirm the chart updates. Check blank handling, labels, dimensions and whether the embedded data can be safely shared. Mark untested if Office cannot be opened. |
| Other | Confirm native support and available integration; map the portable spec to the tool's documented marks, calculations, exports, and accessibility options. | Run a small fixture in the actual target. State what was built, what is editable, and what still needs user-side verification. |

Primary docs: [Figma MCP write access](https://developers.figma.com/docs/figma-mcp-server/write-to-canvas/) · [Power BI accessibility](https://learn.microsoft.com/en-us/power-bi/create-reports/desktop-accessibility-creating-reports) · [Matplotlib export](https://matplotlib.org/stable/api/_as_gen/matplotlib.pyplot.savefig.html) · [D3](https://d3js.org/).
